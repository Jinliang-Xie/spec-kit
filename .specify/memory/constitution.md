# 项目宪章

本宪章定义本项目的目标与原则，聚焦于方向与边界，不在此处规定实现细节或指标阈值。所有细节（指标、算法选择、字段级 Schema 等）应进入规格（spec）、计划（plan）与 ADR 文档中维护。

项目主题：将 LLM 集成到 Python 工作流中，从专利说明书萃取文本中提取与刻画 “工步（技术层面上不可再分的工序）” 图谱，涵盖实体、关系与参数等，并通过跨文档聚合等方式形成可复用的工步图谱。

## 一、范围与阶段性产出

1) 第一阶段（工步识别）
- 目标：结合 LLM 和代码，从前期萃取专利说明书文本得到的 JSON 文件中识别并结构化工步，包含输入/输出、设备类型、操作模式、反应/操作条件、环境等要素；识别工步之间在逻辑层面上的串行与并行关系。
- 产出：将 Patent、Step、 Step之间的关系、各种参数、Patent时间、实体与参数之间的关系等信息写入 Neo4j，完成第一次可视化（各个专利内部的工序图谱）。

2) 第二阶段（工步编码/统一刻画）
- 目标：结合 LLM 和代码，基于一致的一系列原则在三大维度对工步进行统一刻画：
  - 能量形式转换（涵盖机械能、热能、化学能、电能、辐射能、核能等能量形式之间的转换，多种转换可同时发生）与数值的增减，能够以能量转换张量描述；
  - 物质形态转换（涵盖动量传递、热量传递、质量传递、化学反应等子维度，子维度可以进一步细分，多种转换可同时发生）与数值的增减，能够以物质转换张量描述；
  - 信息转换（涵盖信息采集、信息处理等子类型，多种转换可同时发生）与数值的增减，能够以信息转换张量描述。
- 产出：在 Neo4j 中将维度与细分维度映射到图谱并完成第二次可视化（统一刻画后各个专利内部的工序图谱）。

3) 第三阶段（工步原子化：拆分/细化）
- 目标：结合 LLM 和代码，在编码结果与文本证据的共同约束下，将含有多维度/子维度“多值”或“复合动作/条件”的工步拆分为更基础、粒度一致且当前认知下“不可再分”的原子工步；保持先后/并行关系不变并显式化。
- 产出：在 Neo4j 中将原子化后的 Step 集合与关系（保留与原复合工步的溯源关系）进行第三次可视化，为后续聚类/同一化提供一致粒度的输入。

4) 第四阶段（工步聚类）
- 目标：结合 LLM 和代码，以聚类/相似度分析等方式对相似工步进行合并或“同一化”标注，得到与具体输入输出/参数弱相关的可复用、可迁移工步集合；对相同工序进行节点融合。
- 产出：在 Neo4j 中形成跨专利的大图谱并完成第四次可视化（跨文档汇总图）。

说明：本宪章不约束具体算法与指标，相关阈值与评估方法在计划与评测文档中定义并迭代。

## 二、方法与数据原则

- 充分模块化：项目要足够模块化，方便用户在 VS Code 终端中查看逐步结果；逐步结果在用户确认后自动保存在项目特定文件夹中，便于逐步优化与调试。
- 真实与溯源：所有信息必须来源于本发明的技术方案与实施例，避免背景技术内容；为每条结构化结果保留出处（专利号、段落/页码、片段）。
- 反幻觉：输出必须通过严格的 Schema 校验；未知/缺失以显式“未知/无数据”处理，不猜测。
- 可复现：记录提示（prompt）、模型与参数版本；同一输入同一配置应产生稳定输出。
- 渐进完善：先保证“可用的端到端流程与可视化”，再逐步提高抽取质量、刻画完备度与聚合效果。
- LLM 集成方式：优先在 Python 环境中通过 CLI 方式调用 LLM（统一封装、可替换为 API），并对调用的 prompt、模型与参数、输入/输出快照进行记录与可追溯。
- 参数归类：温度、压力、气氛、时间、搅拌转速、流量等反应/操作环境与条件统一归为“参数”，与工步保持明确关联并保留单位与原始取值。

## 三、图谱建模与写入原则

- 极简 schema：首版仅包含必要对象与关系，避免过早复杂化。
  - 核心节点：Patent、Step、Dimension（维度/子维度）、Parameter（环境/条件/配方参数）、Cluster（或 CanonicalStep，用于同一化）。
  - 核心关系：HAS_STEP、PRECEDES（或 NEXT）、HAS_DIMENSION、HAS_PARAM、DERIVED_FROM/COMPOSED_OF（原子化溯源）、SAME_AS/IN_CLUSTER。
- 稳定标识：对 Step 等核心实体生成稳定可复检的 ID（基于来源与文本片段）；写入采用幂等策略（MERGE、批次标记）。
- 版本与可回滚：图写入记录批次与版本，支持按批次回滚与重放。

## 四、质量与评估（高层）

- 评估维度：抽取正确性与完整性、刻画一致性、聚合合理性、图谱一致性与去重、端到端体验（含可视化与查询）。
- 度量与阈值：在计划/评测文档中定义，并随数据规模与领域覆盖逐步收紧；合入前需通过既定质量门。
- 人工复核：保留小型黄金集与抽样复核机制，用于回归与异常定位。

## 五、工程与安全（简要）

- 工程基础：代码风格统一（格式化与静态检查）、类型友好、错误分层清晰；小步提交与评审；依赖与配置可审计。
- 安全合规：尊重专利文本使用许可；凭据通过安全方式注入；避免输出/持久化敏感信息。
- 可观察性：基础日志与最小必要指标，用于定位抽取/写入/聚合故障。

## 六、文档与边界

- 文档分工：本宪章只给原则与边界；规格（spec）描述“要做什么”；计划（plan）确定技术路径、算法与阈值；ADR 记录关键取舍。
- 非目标（当前阶段）：不构建复杂的产品化 UI 与权限系统；不在宪章中固化具体模型/算法/参数；不在此处定义字段级细节与测试用例。

— 本宪章的修改应通过 PR，并在变更说明中阐明动机与影响；细节更新优先进入相应的 spec/plan/ADR 文档。语言策略：英文为准，并提供以 `.zh-CN.md` 结尾的中文对照文件。
